# SECURITY.md — Secure Marketplace

Every row maps a vulnerability to the code that prevents it and to a test you can repeat.
Rule numbers refer to `CLAUDE.md`. Each defensive line in the code carries a `// SECURITY:` (PHP) / `# SECURITY` (YAML) / `{# SECURITY #}` (Twig) comment explaining what it prevents.

**Setup for the tests**

- App: `https://127.0.0.1:8001` · demo data: `php bin/console doctrine:fixtures:load -n` · every demo password: `Password2026!`
- Accounts: `admin@shop.test`, `seller1..3@shop.test`, `buyer1..5@shop.test`
- Burp Suite: proxy the browser, then use **Repeater** to replay/modify requests. DevTools (F12) is enough for most tests.
- `curl` on Windows Git Bash: run `export MSYS_NO_PATHCONV=1` first, otherwise Git Bash rewrites arguments such as `//evil.example` before curl sends them.
- If you repeat a brute-force test, reset the limiters with `php bin/console cache:pool:clear cache.rate_limiter`.

| Secret | Dev | Prod |
|---|---|---|
| `APP_SECRET` (HMAC key: reset tokens, signed URIs) | `.env.local` (git-ignored) | `php bin/console secrets:set APP_SECRET --env=prod` |
| `APP_ENCRYPTION_KEY` (IBAN encryption, 64 hex chars) | `.env.local` | `php bin/console secrets:set APP_ENCRYPTION_KEY --env=prod` |
| `DATABASE_URL` | `.env.local` | real env var or secrets vault, with a least-privilege DB user |

Generate values with `php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"` (APP_SECRET) and
`php -r "echo bin2hex(sodium_crypto_secretbox_keygen()), PHP_EOL;"` (encryption key).
The committed `.env` / `.env.dev` contain no real secret values. Note: an older dev `APP_SECRET` exists in git history (Symfony's default recipe committed it in `.env.dev`); it was removed and rotated during the final review.

## 4. Known limitations (documented trade-offs)

- **Registration reveals that an email is already registered** ("already registered"). Fixing this needs an email-confirmation flow (`isVerified` exists but is not enforced at login yet).
- **Timing side channel on "forgot password"**: when the account exists, a token is generated and an email is sent synchronously, so that response is slower. The content is identical, but a careful attacker could time it. Fix: send mail asynchronously (Messenger worker).
- **Lockout message differs from the rate-limiter message**, which lets an attacker who rotates IPs learn that an account exists. Accepted because the lockout can't be bypassed.
- **Account lockout can be abused for a 15-minute denial of service** on a known email. Mitigated: short duration, live sessions are not killed by it.
- **TOTP secrets are stored in clear text** in the database (needed to verify codes). They could be encrypted with `FieldEncryptor`; not done to keep the 2FA bundle integration simple.
- **Demo fixtures** use one known password for every account: dev/demo only, never load them in production.
- **Local DB uses `root` without password** (XAMPP dev). Production needs a dedicated least-privilege user.
- **The web profiler (dev only)** relaxes the CSP (`'unsafe-inline'` is ignored by browsers when a nonce is present) and records submitted form data, including the fake card number. It is not installed in prod.
